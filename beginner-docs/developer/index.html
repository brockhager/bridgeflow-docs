Developer Quick Start (bf_employee)

This short guide is for developers working on BridgeFlow. The team refers to the developer role as bf_employee. Follow these steps to get productive fast.

  1. Follow the parent quick start:
  2. cd bridgeflow → pnpm install → pnpm run railway:setup
  3. Start services:
  4. Backend API: pnpm run api:start (port 4000)
  5. Frontend dev server: pnpm run web:dev (port 3000)
  6. Run tests locally:
  7. pnpm test (full suite) or pnpm run test:api
  8. Ensure each test file calls await resetTestDatabase() (see test/utils/resetDb.js).
  9. Common dev tasks:
  10. pnpm run prisma:generate after changing prisma/schema.prisma
  11. Run workers locally: pnpm run worker:s3-flush:once
  12. Conventions & gotchas:
  13. ESM-only: use import / export.
  14. Do not enable BRIDGEFLOW_DEV_ADMIN in CI (it hides auth issues).
  15. Tenant isolation uses AsyncLocalStorage + Prisma middleware (api/lib/tenantContext.js).

Where to learn more: - Onboarding & dev orientation: docs/ONBOARDING.md - Architecture: docs/ARCHITECTURE.md - Agent guidance: .github/copilot-instructions.md

If you need help, see the parent guide or contact the repo owner listed in docs/ONBOARDING.md.
