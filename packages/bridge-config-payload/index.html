Bridge Configuration Payload (BRIDGE_CONFIG)

This special package type is generated by the Canvas Assembly UI (deployBridge.js) to provision integration resources.

Payload Structure

When the Canvas sends a package with type: "BRIDGE_CONFIG", the payload is a JSON string containing:

{
  "metadata": {
    "type": "bridge-configuration",
    "generatedBy": "bridge-canvas",
    "timestamp": "2024-01-08T12:00:00Z",
    "blueprintId": "bp_healthcare_payer" // Optional, if based on a template
  },
  "components": [
    {
      "id": "comp-1",
      "type": "trading-partner",
      "tpId": "tp_walmart_123", // Reference to existing entity
      "name": "Walmart",
      "config": { ... }
    },
    {
      "id": "comp-2",
      "type": "connection",
      "subtype": "as2",
      "config": { "url": "...", "cert": "..." }
    }
  ],
  "connections": [
    {
      "id": "conn-1",
      "source": "comp-1",
      "target": "comp-2"
    }
  ]
}

Processing Logic

  1. Validation: Backend validates that referenced tpIds exist and user has permission.
  2. Provisioning:
    • Creates Bridge entity in database.
    • Generates docker-compose or Kubernetes manifests for the runtime.
    • Starts the integration routes.
  3. Activation: Sets package status to PROCESSED (Active).
