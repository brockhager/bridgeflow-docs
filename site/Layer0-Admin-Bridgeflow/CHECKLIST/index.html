Admin Bridgeflow CTO Demo Checklist ✅

Follow these steps to verify Phase 13 readiness during the live demo.

  1. Environment & Access
  2. Start API in secure dev mode (see start/api-start.ps1 or pnpm run dev:secure).
  3. Confirm admin dev account available (use _dev/login or the fallback route for demo).

  4. Ensure REQUIRE_AUTH=true and ENFORCE_RBAC=true for realistic checks.

  5. Security first ✅

  6. Login as admin and demonstrate MFA flow (use dev stub: TOTP 123456).

  7. Show audit logs are recorded for admin actions.

  8. Tenant Management ✅

  9. Search for a tenant in Tenant List.

  10. Use "Login As" to impersonate a user and show a quick audit entry.

  11. Account management (critical paths) ✅

  12. Suspend an org (provide a reason), confirm owners receive notification and processing is paused.
  13. Reactivate the org, schedule backlog processing, confirm backlogProcessingRequested flag and notification.

  14. Demonstrate manual data correction (name/status change) and show rollback metadata in the audit entry.

  15. Health & Operations ✅

  16. Open Metrics dashboard (p50/p95/p99 cards, request volume chart, alerts list).

  17. Trigger a simple job via API and show it appearing in Operations; demonstrate retry.

  18. Emergency Controls ✅

  19. Perform Global Pause → Resume, show env vars are set/cleared and metrics are reset.

  20. Use Clear Cache (metrics) and show metrics cleared without Redis available.

  21. Acceptance Criteria

  22. CTO can perform tenant suspend/reactivate without dev help.
  23. Metrics/Health show realistic data and alerts.
  24. All admin flows produce audit entries.
  25. No crashes or console errors during demo.

Notes & Known Issues (to mention during demo) - We have intentionally excluded two non-critical test suites from Phase 13 gating: - api/tests/users.test.js — Vite transform failure - api/tests/worker.integration.test.js — memory allocation failure in full-run - Both items are scheduled for Phase 14 triage and fix.
